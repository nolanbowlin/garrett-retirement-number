How the two versions work

Open a preview to see what a recipient sees. Open a template only if you are wiring it into a sending tool. The preview is generated from the template, so they cannot disagree.

1
Edit the template
Change layout, structure or the fixed copy. Leave the {{tokens}} alone.
2
Edit the data
Change the sample content in preview-data.json.
3
Rebuild
Run node build-previews.js from this folder.
4
Review
Open the preview. It fails the build rather than shipping a visible token.

Never edit a preview directly. It is a build artefact and anything typed into it is gone on the next run. Every preview also carries a banner marking it as not approved for sending. Take that banner off deliberately, not by accident.

The rules

What applies to every send

RuleWhy
The firm disclosure block is not editableIt is Garrett's registered disclosure, not boilerplate. Trimming it for design reasons is a compliance problem, not a layout choice.
Nothing sends without a review IDEvery approved public piece carries a Guardian advertising review ID and expiry in the footer. There is a {{review_id}} token waiting in each template.
Market commentary stays descriptiveNo forecasts, no performance figures for a named holding, nothing that reads as a recommendation. If a send has nothing safe to say there, delete the block rather than reaching for something.
Physical address and unsubscribe are requiredCAN-SPAM, on all of it.
Never overwrite a published imageThe asset host caches hard and mail already delivered cannot be repaired. Change means a new filename.
Watch the file sizeGmail clips a message over roughly 102KB and hides everything after the cut, including the unsubscribe link. The largest template here is 28KB.

Full detail on all of this is in ../brand/peachtree-brand-package.html.
